## Shipped defaults

Use [the maintained capture workflow](../development.md#capture-current-defaults) when asked to replace the baseline. It confirms save completion, reuses the portable preference boundary, backs up the previous files and records [capture metadata](../../config/XIUIplus-defaults.capture.json). Ordinary builds preserve the captured baseline and active user settings.

The October 17, 2026 baseline was refreshed from Cody's live 23:58:29 save and captures the complete current UI configuration: 14,320 saved preferences across 1,867 sections, including enabled states, positions, text, colors, bars, status effects, minimap options, action bar settings and the current theme. Empty/retired demo settings, profile metadata and session data are excluded. New installations and explicit Reset to defaults use this baseline; existing installations retain their own saved preferences.

The default HUD font is **XIUI (Bahnschrift)** in both `[global.text]` and individual text styles. **Three-dot menu â†’ Reset to defaults** opens a themed warning with Cancel selected. Explicit Reset restores all XIUI preferences and positions, including disabled modules, both chat windows, status effects, inventory and alliance lists, regardless of the selected category. Mouse, keyboard and controller share this action; held confirmation cannot repeat it. Existing custom settings remain until an explicit reset; the immutable portable-sharing preset remains unchanged.

`config/xiuinative-defaults.ini` is the captured default profile, embedded as runtime resource 301. A missing user INI loads this profile through `settings_store::FromIniText`, then queues a complete normal save. Existing files retain their own values. `/xiui reset` and the confirmed menu action restore the complete captured profile through the registered modules, the same load paths and asynchronous writer, including layout and configuration bounds; the gameâ€™s own Window Type remains authoritative. In-memory INI reads are case-insensitive and use explicit fallbacks for absent keys. `/xiui save` queues the current settings without leaving edit mode. `xiui_config_input_smoke --defaults-only config/xiuinative-defaults.ini` checks the embedded bytes, first install, existing settings and reset behavior, including Bahnschrift defaults, cancellation, exactly-once mouse/controller activation and complete preference round trips.

`scripts/package.ps1` builds `xiuinative_release` and publishes one standalone `dist/xiuinative.dll`. `XIUI_SINGLE_DLL` binds the host directly to the embedded runtime API and disables companion-file polling, shadow copies and runtime DLL loading. The separate host/runtime targets remain available for development hot reload. The release statically links its C++ runtime and embeds the captured theme (resource 302), icons, cursors and notices. First use creates missing theme and notice files without replacing existing files. `VERSION` drives the Ashita version, startup version and Windows file/product version. CMake tracks version changes and the defaults resource payloads explicitly, so incremental releases rebuild captured preferences, theme and bundled notices when those files change. `xiui_single_dll_smoke` loads the release in an isolated folder containing only that DLL, creates the actual Ashita plugin, initializes its embedded UI, routes saving and confirms generated settings/theme files. No development bridge is bundled. Window themes and native item artwork are read from the installed client; the original XIUI notification PNGs are embedded alongside the XIVParty job icons.

`scripts/pack-resources.py` losslessly packs raw BGRA atlases/cursors and the mob database into build-generated `XZIP` resources (original byte count plus a zlib stream). CMake tracks input payloads and generated outputs for incremental rebuilds. `resources::LoadEmbeddedResource` bounds allocation, validates decompression and retains raw-resource compatibility. Texture uploads release temporary decoded bytes; the mob database owns decoded storage for its record/name views. Font, sound and text resources retain their existing lifetime and raw format. The minimap bundle keeps its `XMAP` zone/floor/style index and all 662 entries, with 512-pixel WebP quality 90 images rebuilt from original sources by `scripts/build-minimap-maps.py` (`--cached` reuses original downloads). A statically linked libwebp decoder runs through the existing worker and eight-texture cache; WIC remains a fallback for legacy images. Decoder licenses are embedded and seeded with the other notices. Packaging runs `xiui_resource_smoke` against the actual release DLL to check exact decompressed asset bytes, allocation/checksum failures and regular/enhanced WebP decoding before the standalone startup check.

`scripts/build_all.ps1` defaults to the checked standalone DLL and the explicit Phoenix install path (`-InstallPath`, `XIUI_INSTALL_PATH`, or the current development installation). SDK discovery is independent of deployment. The optional host/runtime build requires `-Development`; the watcher requires its install path and checks the installed development host before publishing.

Settings snapshots merge into existing INI text and publish with one atomic replacement. Unknown fields, comments and UTF-16 encoding remain intact; unchanged values avoid rewriting. The asynchronous writer still coalesces full snapshots and retains failed work for retry. Non-finite numeric values use the setting's fallback at the shared reader.

Optional icon atlases load on first acquisition through the shared cache. Device/resource changes and shutdown release all acquired textures; unused feature artwork and unselected themes stay unallocated. Incoming combat action packets share one immutable decode and timestamp across their consumers.

## Configuration presentation

`config/config_session.hpp` owns configuration selection, bounds, scrolling, focus, search and active editors. `hud_runtime_config.cpp`, `hud_runtime_config_input.cpp` and `hud_runtime_config_render.cpp` handle module coordination, pointer input and drawing; controller adapters use the same session and toggle activation. Lifecycle, persistence callbacks and native input routing remain coordinated by `hud_runtime`. Cancel editors and release owned input before replacing settings or leaving a surface.

`combat_settings` owns the shared Retail/Horizon/Phoenix rules in the runtime. Action Bars and Phantom Roll edit that object through the shared choice controls; gameplay sources consume `server_rules`. Loading retains the existing `actionbars.skillchain_rules` â†’ `magicburst.rules` â†’ Retail precedence. Capture/save writes the canonical key and compatible `phantomroll.rules` mirror once, so profile snapshots, search, resets and hot reload use the same owner.

The profile three-dot menu offers **Rename profile** for custom profiles; Default is protected in both the UI and storage. Rename reuses the shared name dialog and validation, drains pending saves, and changes only the display name in the existing profile file. Stable IDs, character bindings, settings and positions stay intact. Pointer, keyboard and controller share the same commit action.

Use `module_option::VisibleWhen` for settings that depend on another preference. Hidden controls retain their values and are excluded from layout, search, pointer input and controller focus; hiding an active editor cancels its draft. Compose visibility with shared text/meter dependencies. Reserve `available` for capability or action availability so diagnostic messages remain visible.

Action Bars separates Hotbars/Crossbar settings from Actions & Macros, Action Sets and Import destinations. Management uses compact independent workspace windows, with the shared native container, config header/close/grip geometry, resize constraints, controls and cursor renderer. Window visibility, text capture, deliberate navigation and owned pointer gestures remain separate. Clicking another window preserves the workspace and its draft; closing Configuration leaves it open. Library drops retain their press through release and reject slots obscured by Configuration. Workspace bounds persist separately from HUD module bounds.

Keyboard shortcuts follow the native Keyboard Size setting. Compact 1/2 retain gameplay character shortcuts, including F-to-focus. Full mode leaves unfocused letters, digits, punctuation, Space and Shift-only text with native chat; global hotbar actions use modifier or function keys instead. Missing native settings also preserve ordinary typing. Explicitly focused editors, dialogs, binding capture and deliberate browsing retain their own keys. `input/keyboard_policy.hpp` supplies the shared mode/text-key rules; owned presses and releases drain before applying a changed mode. Do not make mode-aware fixes by removing Compact shortcuts globally.

Shared configuration text inputs use a softly rounded inset surface from the native window palette, with no outline stroke. Typing focus uses a subtle `control_selected` underline and caret; invalid values use an error underline. Placeholders and optional trailing shortcut hints use muted configuration text.

Settings search enumerates existing control metadata in an isolated runtime loaded from the current preference snapshot. It retains module/view/topic, presentation-selector and special-tab paths, then navigates the live controls through their ordinary selection hooks. Indexing never mutates live controls or calls native setters; opening a result does not invoke its value/action. Hidden categories may be inspected transiently without enabling them. The header search icon expands into the input over 180 ms, with shared animated bounds for drawing, pointer hits and controller focus. The typed-query X and controller Actions share Clear, retaining typing focus. Query text and result focus are transient; keyboard composition ownership ends on close or foreground loss. See [Configuration window](../reference/configuration.md).

Configuration uses shared responsive geometry for one or two option columns, selector wrapping, mixed-height preset cards and custom lists. Edge/corner dragging, Alt+F8 and controller resize actions share viewport/minimum constraints. Preview resizing retains committed dimensions until confirmation; Cancel restores them. See [Configuration window](../reference/configuration.md).

Configuration reopens on its last category, module view and settings page; reloads retain that selection. New installations and missing selections start on General. Navigation is saved under `[session.config]` using explicit topic identities with legacy ordinal fallback, and excluded from portable profiles; unavailable categories fall back to General. Controller focus, held input and unfinished editors remain transient.

Follow [settings organization](../reference/settings.md) and the [audited inventory](../reference/settings-inventory.md). Presentation order is separate from option IDs and persistence. Dimensions come before position/offsets, spacing and container styling; width/height and each X/Y pair share a row. Text starts with font and size. `module_option::Ordered` and `config/option_layout.hpp` supply the shared slots used by rendering, pointer input, scrolling and controller navigation. Empty cells preserve related pairs without becoming focus targets. New settings must retain these conventions.

`module_option::ToggleButtons` groups independent booleans into one setting row with labeled ON/OFF buttons. Drawing, pointer hits and individual keyboard/controller focus targets use `config_layout::ToggleButton`; all activation paths call the same toggle operation. Each value retains its module's existing persistence key.

## Containers

`ui::nine_slice_skin` describes nine texture views with source rectangles, native texture dimensions, per-vertex colors, and blend settings. `LayoutNineSlice` covers conventional nine-slice panels. `LayoutNineSliceFrame` supports thin borders with larger corner fades and a continuous background underneath. Corners stay fixed as a window changes; edges and the background repeat at their source texture density. Tiny windows clamp corner sizes without inverted rectangles.

Configuration, equipment and status tooltips share `container_renderer::DrawTooltip`. Its opaque dark backing and shaded plain native background retain the selected Window Type, with a compact 2.5-pixel frame and the existing 13-pixel content inset. The frame scales uniformly to fit short or narrow bounds, keeping corner artwork from being squeezed into the opposite edge. Tooltip text retains its normal configuration or HUD profiles and effects.

`ui::container_renderer` reads all eight installed Window Type DATs through Ashita's resource paths, file IDs 14â€“21 (`ROM/0/14.DAT` through `ROM/0/21.DAT`). General â†’ Appearance â†’ Window theme changes the client's actual Window Type for the whole game, including native menus, chat and XIUI. The control reads the live client value, queues a change for the game thread, and calls the uniquely validated native config setter for record `0x12`, preserving its callbacks and normal client persistence. It stores no XIUI override and does not reset the game setting when XIUI defaults are restored. Unsupported clients show the option as unavailable. `/xiui theme` opens the control; `/xiui theme 1` through `8` request the same native change. It follows Menu â†’ Config â†’ Windows â†’ Shared â†’ Window Type through the native config record (key 0x12, zero-based selection). The host resolves the config manager with a unique validated signature and checks the record ID and 0â€“7 range before forwarding it. Skin changes select a cached texture set; they perform no file reads, uploads, or settings writes. `resources::DecodeMenuWindow` decodes the native DXT1/DXT3 images and window definition: background, horizontal border, vertical border, corner texture, UV offsets, vertex colors, and blend modes. The renderer preserves the game's 24-pixel corner fades, 5-pixel borders, double modulation and per-patch blend. Window vertex colors follow the client's load-time conversion: increment non-saturated RGB bytes, retain alpha 0/255, otherwise use `min(255, floor((alpha + 1) * 1.5))`, then keep the existing double modulation and per-patch blend. Raw DAT alpha made Type 6's gold edges too faint. Stock Type 7's right edge has a brighter additive DAT entry than the left side. After native color conversion, the shared renderer narrowly matches that known right-edge signature to the left edge's colors and normal blend, retaining its own UVs and artwork. Other types and customized DAT edge colors remain unchanged. There are no generated replacement pixels or bundled game assets. Textures are uploaded once per device; drawing performs no file reads. The optional plain fill averages the native background's colors.

Every HUD module can use the shared renderer through its render context:

```cpp
ui::container_style style;
style.opacity = 1.0f;
style.padding = 8.0f;
const auto content = context.DrawContainer(windowBounds, style);
// Draw the window's contents inside the returned rectangle.
```

`DrawContainer` also accepts optional `container_fill` overlays, clipped inside the native frame and multiplied by container opacity. Pet Target uses this for its optional background tint while retaining its normal text and meter styles.

For artwork under the frame, draw the container with `border=false`, clip the image to the full window bounds, then use `DrawContainerFrame` with the original style. Pet portraits use this path so text padding does not shrink their clipping region and native corners/edges remain above the artwork.

An October 15 AgentLink read-only probe confirmed the live Type 6 frame: the horizontal border uses diffuse `0x61808080`, and vertical vertices alternate `0x00808080` / `0x0D808080`. The decoder now matches those live vertices exactly. `xiui_config_input_smoke --window-borders-only <Type 6 DAT> <Type 7 DAT> [live left-edge sprite dump]` checks installed DAT decoding, alpha endpoints/clamping, live color equality and the scoped Type 7 right-edge correction. `--type7-edge-only <Type 7 DAT>` checks only that correction, retained artwork and other/custom theme preservation. No settings or opacity defaults change.

The returned content bounds account for trim and padding. Opacity, frame size, padding, and scan lines belong to the style; window position and dimensions belong to its consuming module. A black backing covers the full container bounds beneath both the background and border, making the complete window opaque at 100% opacity while retaining each Window Type's pattern and native frame artwork on top. **General â†’ Appearance â†’ Dark backing opacity** controls this added dark layer from zero to full opacity across XIUI containers, including config, and themed bars. It multiplies the module's existing opacity without changing native artwork, border, cap or fill opacity. It defaults to full opacity to preserve the current appearance, persists as `[appearance] dark_backing_opacity`, and uses the normal asynchronous save path. Header/sidebar tint fills remain clipped to the interior. The default frame size of 5 preserves native artwork scale. Existing generated-skin settings migrate to the native proportions. The standalone container demo and its config section have been removed; the shared renderer still supplies the actual HUD/config windows. Old demo settings are ignored and existing module appearance settings remain intact.

The host/runtime contract is ABI 16 (cached controller routing, native party world anchors the captured scene camera/viewport and borrowed color/depth surfaces for Target Rings). Updating from an earlier ABI requires installing both DLLs with the host unloaded once; subsequent renderer and feature changes hot reload as usual.

Module config no longer exposes Frame size or Scan lines, including the Party status containers. Party, alliance, enemy and chat containers use the shared native frame and patterned background defaults. Old `frame_size`, `edge_size`, `scan_lines` and status equivalents are ignored; opacity, padding, positioning and other preferences remain independent and continue to persist.

`meter_animation_state::Update` shares frame-rate-independent resource interpolation between ordinary HUD meters and the Target Ring HP arc. Reset its transient state on target changes.

Main Target mob-information groups anchor before the changing status grid. Main-target casts draw outside that flow, immediately below the HP track, with their normal meter effects and centered shared cast text. Target > Cast Bar owns width, paired offsets and Below Target / Independent positioning. Independent casts use the Target-owned `target.cast` movement adapter, `layout.target.cast` persistence and shared pointer/controller movement; visibility also follows the parent Target. Cast activity does not change Target layout height. Other target views retain their existing cast presentation. `xiui_config_input_smoke --mob-info-only` checks stable information/status anchors, cast-independent flow, placement controls and persistence.

## HUD text

HUD text uses `module_text_profile` with the shared theme roles: `title_text` for names, `meter_text` for bar labels/values, and `caption_text` for secondary information. Compact modules may adjust scale without clearing shadow, stroke, glow, or gradient settings. Configuration labels use separate config controls with flat colors. General â†’ Appearance â†’ Config Text owns the config font, base text size (8-18 px, default 14), pixel letter spacing, drop shadow and its color/offsets/softness, stroke outline (Off, Buttons only, All text), glow and animated sheen with their colors and sweep settings. Defaults retain a shadow and button-only outline. These preferences apply live to labels, buttons, menus, tooltips, editors and dialogs, persist in `[config.text]` and profiles, and remain independent of HUD text profiles. `config/config_text` owns these controls and persistence; the shared config renderer resolves size and effects while preserving relative heading/help sizes and theme colors. Measurement and drawing apply the config size once; pixel letter spacing remains independent of size.

Render through `module_render_context::DrawText` and `DrawMeter`. Expose profiles through `TextProfileOption` and persist them with `LoadTextProfile` / `SaveTextProfile`. Preserve the configured profile when drawing. State colors use `TintTextProfile` to multiply the text colors while retaining the gradient, alpha, effects, offsets, and placement. Leave untinted text unchanged. Target and Enemy list share this tint path.

Each shared text profile exposes **Show text** before its styling controls. Visibility defaults on, persists per profile and survives tinting and global typography changes. Hidden text draws no glyphs or text hit bounds; meters and other module content remain available. HUD buttons center their labels by default while retaining explicit profile alignment and offsets. Shared button tones preserve native artwork and styled labels; Treasure Pool uses green for Lot/Lot all and red for Pass/Pass all.

`DrawMeter` uses the shared meter text layout for both labels and values. Window theme reserves the DAT cap widths plus text padding on both sides, including when a text profile overrides horizontal placement. Automatic HP/MP/TP labels straddle the top edge while values remain centered inside the bar. Explicit top/bottom anchors remain intact. Its optional value anchor lets EXP inset info at the upper or lower bar edge independently of its label. **EXP label** controls that label's visibility; both text profiles retain their configured effects and offsets.

The shared text renderer supports `text_style::tabular_numbers`: digits occupy the widest digit cell from the existing font atlas, with narrower glyphs centered inside that cell. Measurement, clipping and every base/shadow/stroke/glow/sheen pass use the same metrics from `ui/text_metrics.hpp`; letters and punctuation retain their existing widths. EXP uses this drawing hint through temporary copies of its normal profiles, preserving saved font styling, gradients, effects, offsets and alignment.

Enemy list's old plain defaults migrate once to the corresponding saved Target/Player styles, retaining compact sizes and positions. Existing styled profiles and later customizations remain intact.

**General â†’ Appearance** has Window, **Global Text** and Config Text tabs. Global text size applies the chosen scale to every HUD text profile, including disabled modules, both chat windows, alliance lists, inventory trackers, notifications, attack/rest timers and Target of Target. Global Text also controls font, letter spacing, drop shadow (color, X/Y and softness), stroke outline and color, outer glow and color, and animated sheen (color, width and speed). Its live sample has a reserved area above the scrolling controls. Every global action changes only its selected property across all HUD styles, retaining other styling, colors, gradients, offsets and layout. Later module edits override the last global action and survive saving, profile switching and sharing. New profiles inherit only the global properties that have been applied; existing explicit profile values remain authoritative. `config/global_text` owns these controls and their per-property application flags in `[global.text]`; `settings/text_style_settings` shares property copying and persistence with every module. Profile persistence includes shadow offsets and sheen settings. Notifications use the same full text style while retaining their per-event colors and shared fade behavior. These controls affect XIUI-rendered text, including the command-menu edit placeholder; native game menu text remains owned by the client. The shared text-profile controls also expose a Font dropdown.

Font choices are XIUI's original Bahnschrift, Segoe UI, Tahoma and the supplied Grammara Normal. `ui/font_catalog` owns the catalog and private memory-font registration; the supplied TTF and its original info file are embedded from `assets/fonts`. No Windows font installation or external font file is needed. Text size controls show character size in pixels (8ï¿½38) while retaining the existing saved scale keys, with 1.0 corresponding to 15 pixels. `ui/text_rasterizer` creates each face at the requested size using four-times supersampling and grayscale coverage, independent of Windows font smoothing. Glyphs draw at one texel per screen pixel with aligned origins; text size never stretches an existing bitmap. Measurement, clipping, tabular digits and drawing share native advances, ascent and line height. Party, Enemy List and Action Bars use `ui::FitText` to fit labels without splitting UTF-8 characters. `design_system::TextHeight` supplies layout metrics. Glyphs supported by the selected font retain that face; missing Unicode glyphs use Yu Gothic UI at the same size and align to its baseline. `ui/glyph_atlas` lazily caches size/family/codepoint glyphs in at most sixteen 512-pixel pages with three effect masks, 4,096 metric records and 64 native faces. Batches flush before uploads or page reuse; generations invalidate evicted glyphs. Shadow, outline, glow, gradients and sheen retain the selected face and size. Device changes and shutdown release textures, GDI resources and private Grammara registration. Config labels use their independent Config Text font, with pixel spacing included in element-tab sizing, caret positions, tooltips and wrapped profile keys. Global Text shows a live HUD typography and effects sample. Chat wrapping includes font identity in its cache key, and chat chrome uses a saved profile. `/xiui fonts status` reports available families. `xiui_config_input_smoke --text-rasterization-only` checks native sizes, grayscale coverage for every font, effects, Unicode, stable digits and pixel controls. `--global-text-only` checks shared tab input, preview spacing, all-module typography/effect updates, preserved unrelated styling, independent later overrides, profile round trips, legacy and inherited defaults and actual embedded Grammara selection.

## Bars

Party/alliance text controls distinguish **Bar labels** (HP/MP/TP captions) from **HP values**, **MP values** and **TP values** (numbers). Each value profile has independent shared styling and offsets, used by drawing and layout measurement. HP retains the legacy `text.<list>.values` section; MP and TP migrate once from that loaded profile and then persist separately. **Sync** replaces the former Details label while retaining `text.<list>.details` for compatibility.

**All bars** selects an editing scope. Selecting it never copies a bar's values into the others. An explicit shared edit propagates only that setting through `CopyMeterStyleOption`; heights, appearances, effects and colors otherwise remain independent. Party geometry fields likewise change across bars only when that field is edited. Mouse and controller selectors invoke the same behavior. `xiui_config_input_smoke --all-bars-only` covers both entry paths, all three Party/alliance lists and property-preserving shared edits.

Player HP/MP/TP, Target, Enemy list HP/casts and EXP share the same bar renderer. **Appearance â†’ Bar style** selects **Window theme** (the default) or **Modern** for each module/bar. Player's shared-style mode applies the selection to all three meters; individual mode retains separate choices. Both styles retain smooth fill changes, animated sheen, shadows, outer/fill glow, configured fill colors, and the usual text profiles and placement.

Player and Party/Alliance TP fill in three overlaid 1,000-TP stages: 0â€“1,000 fills the base, 1,000â€“2,000 fills a second tint over the completed base, and 2,000â€“3,000 adds the third tint. Numeric TP retains its actual value. `ui/tp_meter.hpp` derives the layers from one smoothly animated total, preserving the configured base gradient/alpha and adding subtle mint/lavender tints to the later layers. The shared renderer draws the track, caps, border and shadow once, layers only their fills, and applies one sheen across the occupied track. Both Window theme and Modern retain their normal effects and text. **Player Bar â†’ Effects â†’ TP ready blink** controls a subtle one-second brightness pulse at 1,000 TP or higher; it defaults on, stores `[player] tp_ready_blink`, and stops as soon as actual TP falls below readiness. No settings, resource columns or timer geometry are changed. `xiui_tp_meter_smoke` checks stage boundaries, retained underlayers, colors/alpha and pulse behavior without a graphics device.
Window theme uses the installed file ID 1 `gauge` texture and `menu windowps` groups 38 (frame/geometry) and 97 (fill). The frame and fill are isolated with extruded edge texels, then reconstructed at four times their source resolution with bicubic filtering. Bar backgrounds use a separate four-times-resolution copy of each Window Type's DAT artwork; interpolation wraps across tile seams while preserving the original pattern density. Filtering uses premultiplied colors to avoid transparent-edge halos. These textures are prepared once when loading assets and cached across device resets, with native-resolution fallback if the larger texture is unavailable. Other container textures retain their native artwork. Endcaps are redrawn with the shared antialiased geometry and a subtle bevel using the selected theme's chrome, border and accent roles. They retain the DAT proportions while scaling smoothly at any bar height, without allocating textures. A one-pixel gap separates each cap from the bar body; fill and text use that inset, clamping safely on narrow bars. The fill stays inside the native vertical inset. The unfilled track uses the selected Window Type's cached DAT background over a dark backing. The native center frame keeps its vertex shading and blend; the textured fill uses the module's gradient colors. Changing Window Type selects existing cached artwork and updates the cap tint immediately. Modern retains the existing geometric caps, rounding, borders and background gradients. Those geometry/color controls are disabled for Window theme without replacing their saved values, so switching back restores them.

Use `module_render_context::DrawMeter` for bars with animated values and labels, or `DrawBar` for an externally timed bar such as a cast. Both resolve the same cached native skin, falling back to Modern if artwork is unavailable. Gauge textures and skin views are created once per device, with no DAT reads, decoding or uploads during drawing. `appearance=0` selects Window theme and `appearance=1` selects Modern in the existing `[meter.*]` sections; the theme file's `[meter]` supplies the default. Existing profiles without this key adopt Window theme while preserving other preferences. `/xiui theme status` reports whether themed bar assets are available.

**Bookends** is available for both bar styles. Window theme keeps caps on by default; turning them off extends its native center frame, background and resource fill across the full width, with normal text padding and no reserved cap gap. `[meter.*] themed_bookends` persists independently of Modern's existing `bookends` preference. Missing keys retain the previous capped themed appearance. Both bar/text geometry paths share this choice.

Bar dimensions belong together in **Layout**. The shared meter section mapping places Bar height beside module width for Player, Target, Enemy List, Cast Bar, Cast Cost and Recast; Player keeps its All bars / HP / MP / TP strip available there. Party and both alliances use the same mapping, with bar width, height, position and offsets in Layout and the All bars / HP / MP / TP / Cast strip retained. Target of Target keeps width, height and optional cast height in Layout; its custom-style fallback lives in **Bar Style â†’ Automatic bar height** and is available only while the explicit height is zero. EXP already keeps width and height together in Display â†’ Layout. Bar Style owns theme, shape and bookends. Setting keys, option indices, values, shared-bar callbacks and saved layouts remain unchanged.

Party **Cast placement â†’ Replace name** anchors the track to the actual name text position, including its offsets and alignment. Independent cast offsets then apply relative to that anchor. The earlier untouched XIUI preset's duplicate 4/8 cast offsets migrate once to zero so the name offset applies once. Job icons do not reserve horizontal entry space or affect fitted width; their anchors and offsets control drawing independently. Shifted number-only TP contributes its visible text bounds, while out-of-zone panels remain inside the fitted window. Number-only TP reserves the native font's four-digit width plus explicit alignment padding and draws the complete number without abbreviating it.

Player attack and resting tickers default to **Mini bar**, each with a **2-pixel gap** from TP or HP. Constructor, missing-key fallbacks and the shipped profile agree; existing explicit preferences remain authoritative.

**Bar height** controls the actual track thickness in pixels through `LayoutMeterTrack`, centered within the module's reserved row. Text and taller neighboring bars can reserve more row space without enlarging the selected bar. Modern outlines, shadows and glows extend beyond the track. A zero saved height retains automatic sizing; the slider offers explicit heights from 1 to 80.

`xiui_config_input_smoke --bars-only [ROM/0/1.DAT]` checks capped/uncapped geometry, exact track heights, independent/shared style choices, persistence, older settings and native artwork extraction alongside existing text placement checks.

## UI sounds

`ui::native_ui_sounds` resolves the client's own cursor (`0001`), confirm (`0002`) and menu-opening (`0013`) resource wrappers with unique, guarded signatures. These retain native sound assets and game volume settings; unsupported clients stay silent. Config opening plays the menu sound, entering an available control plays the cursor sound, and each click or accepted numeric commit plays confirm once. Color controls share the same routing. Hover does not repeat while resting on a control or dragging. Runtime state restoration is silent.

The same feedback covers Ready Check buttons, equipment-slot hover, chat tabs/channel/input/completion controls, and clickable party/enemy rows. Equipment hover remains read-only and does not capture input. Chat submission plays the native confirm/send sound only after a valid message is queued; empty, recipient-only and rejected drafts stay silent. `/xiui sounds status` reports native support. Focused `--sounds-only` modes in the config-input and chat checks use mock playback and never send live messages.

**Chat â†’ Sounds** shares alert preferences between both chat windows. Each chat type has a dropdown offering **Off**, **Menu chime**, **Confirm** and **Cursor**, using native audio and game volume settings. Incoming tells default to Menu chime; outgoing tells, Say, Party/alliance, both Linkshells, Shout, Yell, Unity, Emotes, Other chat, Combat and System default to Off. Existing on/off preferences map to Menu chime/Off. The comma-separated **Keywords** field matches words or phrases anywhere in captured chat, ignores case (including Unicode), trims surrounding spaces and skips empty entries. A blank list disables keyword alerts. **Keyword sound** has its own dropdown and takes priority when both a keyword and chat type match. Inline color changes do not interrupt matching. Each captured message plays at most one alert; delivery to both native windows and restoring history during runtime replacement stay silent on duplicates. Disabled chat and hidden XIUI suppress alerts. `[chat.sounds]` persists sound selections and keywords through normal saves and profiles.

**Chat â†’ Colors** has one shared Game/XIUI source switch and color picker per chat type. All types default to Game. The panel explicitly states that XIUI colors override your game settings colors. Picking a swatch enables that type's override; choosing Game restores native mode/inline colors while retaining the custom color. XIUI colors apply consistently to both chat windows and the matching input channel/command prefixes, including existing scrollback. They do not write the game's palette. `TintTextProfile` preserves normal gradients and text effects. `[chat.color.<type>]` stores the override flag and RGBA color. `xiui_chat_smoke --customization-only` checks native sound routing, legacy selections, keyword priority, color precedence and persistence; `xiui_config_input_smoke --chat-customization-only` checks actual dropdown selection, popup ownership, color sources and keyword editing.

**Chat/Chat 2 â†’ Animation â†’ New messages** offers Off, Fade + slide up (default), and Fade + slide right from the left. **Animation speed (%)** ranges from 25â€“300%; higher is faster and 100% retains the original 220 ms entrance. Each window saves `message_animation` and `message_animation_speed` independently. A newly enabled second window initially follows the first window's presentation; later changes stay independent. Entrances move 14 pixels, keyed by message sequence with at most 128 active records. Timing and expiration use the same scaled duration. Wrapped lines, inline channel colors, separate timestamp colors, normal text effects and auto-translate caps share one fade/motion. Native-window duplicate delivery starts only the newly matching window's entrance. Captured-history replay is silent; scrolled/expanded history, filter/speed changes, clearing and settings loads release transient animation state. Draft editing, caret placement, controller actions and game input ownership keep their existing behavior.

`design_system::clip_scope` bounds active entrances to the log and restores prior clipping on scope exit. `ui/clipped_quad` crops glyph/effect and native auto-translate texture geometry while interpolating UVs/colors, without changing device clipping or normal unanimated drawing. Content bounds follow the clipped footprint. `xiui_chat_smoke --message-animation-only` covers direction/progress, routing/duplicates, replay/scroll suppression, bounded state, preferences and cropped art geometry.

`xiui_chat_smoke --animation-speed-only` checks original/faster/slower timing, expiration, shared-slider routing, independent saved speeds and reset/invalid-value fallbacks. The slider is disabled while New messages is Off and keeps its saved value.

Sound dropdowns also include the original ChatMon Tell, Talk, Emote, Examine and Invite WAV clips from [Windower/Lua](https://github.com/Windower/Lua/tree/1ff0a819b952366a06bf75a8484803f9eee59db4/addons/chatmon/sounds). They are embedded in the DLL with their BSD notice, which is also extracted to `config/xiuinative-licenses/ChatMon-Sounds.txt`; no ChatMon installation is needed. These clips use Windows audio volume. Native choices and existing saved selections retain their current behavior. `embedded_sound_player` caches the embedded PCM data, uses its own asynchronous wave output and stops/unprepares its buffers before runtime unload, without interrupting another addon's audio. Each audible dropdown row has a play icon; it previews without a confirm cue, changing preferences or closing the list. Space previews the highlighted row, held keys do not repeat, and the footer explains scrolling/previewing. Off has no play button. `xiui_chat_smoke --chatmon-only` checks embedded resources and playback routing with mock callbacks; `xiui_config_input_smoke --chat-preview-only` checks pointer/keyboard previews, scrolling, input capture and ordinary selection without playing live audio.

Module text fields reuse the shared native styled text editor with selection, clipboard, Unicode input and horizontal caret scrolling. Enter/Tab applies, Escape cancels, and clicking elsewhere applies before the next action; navigation/focus loss cancels stale editing. The keyword field accepts 500 UTF-8 bytes, while profile names retain their 64-byte limit. The profile dropdown uses chevron atlas icons; add and close controls use matching supersampled plus/cross icons with shared native button faces. `xiui_chat_smoke --alerts-only` checks defaults, routing, keyword matching, duplicate/replay silence and persistence; `xiui_config_input_smoke --chat-alerts-only` checks field editing and keyboard ownership.

## Settings persistence

The bottom-left profile dropdown, **+** and ellipsis buttons share one row without a header and manage named UI setups. Default captures the existing working configuration. The plus button opens a native themed Create profile dialog with a keyboard-focused name field, Create/Cancel, Enter/Escape, selection, clipboard and Unicode input. Names are trimmed and checked for case-insensitive duplicates; filesystem IDs are independent of display names. The dropdown supports mouse selection, wheel scrolling and keyboard navigation. Dialogs and open dropdowns own pointer/keyboard input before the config and movement previews.

The adjacent ellipsis menu offers **Duplicate profile**, **Share profile**, **Import profile** and **Delete profile**. Duplicate opens a named copy of the selected saved profile and selects it after creation; later edits remain independent. Share chooses the smaller of a compact `XIUI2` key and the original `XIUI1` format. XIUI2 stores differences against the immutable `assets/profiles/share-v2.ini` preset (resource 305, CRC32 B0E857FE), including removals and fields from newer modules. This preset stays separate from changing release defaults, so the complete original preferences are restored across versions. Both formats retain bounded compression and checksums; existing XIUI1 keys remain importable. Session totals and active-profile metadata remain excluded. Share and Import use the same wider dialog, padded fields and aligned actions. The complete wrapped key is always visible, with scrolling and no ellipses. Copy key / Ctrl+C copies the complete value. Keys contain the portable setup and need no account or external service. Import accepts a clipboard key through Paste key, the key field or Ctrl+V, suggests an unused name, and enables Import only after a valid key is loaded. Clipboard whitespace is removed from the displayed key; invalid keys mark the key box rather than the profile name. Import creates a separate profile. Existing profiles and live sessions remain intact. Invalid, damaged or oversized keys leave the current setup unchanged. `xiui_config_input_smoke --profile-sharing-only` checks compact key sizes, the fixed preset, changed/new/removed fields, legacy compatibility, complete snapshot round trips, visible keys, exclusions, import naming, damaged data and existing profile persistence without modifying the real clipboard.

Delete opens a confirmation naming the selected profile, with Cancel and a red-tinted native Delete button. The name is read-only; Cancel is the initial keyboard selection, Tab/Left/Right switches actions, and Enter activates the selection. Escape, Cancel and close dismiss without deleting. Default is protected, and its delete action is disabled. Confirming drains pending writes, reads Default, removes the selected profile file and switches to Default without overwriting its layout or live session data. Failed writes, an unavailable Default or a failed file removal leave the current profile selected. The shared button renderer supports a danger tone without changing normal button styling or config text effects. `xiui_config_input_smoke --profile-delete-only` checks confirmation input, cancellation, failed removal, Default protection/fallback and saves after deletion.

Profiles copy the current layout and module preferences, become active when created, and autosave through the shared asynchronous writer. Files live in `config/xiuinative-profiles`; `[profiles] active` in the working `xiuinative.ini` remains the compatibility fallback. Local `[profiles.characters]` entries remember each character's profile and restore it at login or runtime replacement. Validated login/entity identity plus the selected login record supply world/character IDs; unsupported character-list lookups fall back to installation-local character IDs. Unknown or mismatched identity suspends profile autosaving. New identities drain pending writes, cancel transient confirmations/focus and load their bound profile while retaining chat drafts and session data. Missing profile IDs fall back to Default; an unsupported/unreadable profile retains committed settings and suspends autosaving until explicit selection. Selecting, creating, duplicating, importing or deleting a profile updates only the current character binding. The `profiles.*` namespace is excluded case-insensitively from profile files, preference overlays and share keys. `xiui_config_input_smoke --character-profiles-only` checks restoration, pending-write ordering, identity loss, failure/fallback, explicit recovery and portability in temporary settings. Switching drains both writers before reading the destination, overlays only presentation preferences on the current settings snapshot, and keeps the normal live module objects. `session.*` sections and profile metadata are excluded from profile snapshots and overlays, preserving EXP/gil session totals and history. Missing/unreadable profiles leave current settings selected. The shared dropdown, text-input and native-dialog presentation retain config styling and sound feedback. `xiui_config_input_smoke --profiles-only` covers creation/cancellation, validation, keyboard/pointer ownership, copying, autosave, switching, persistence, minimum sidebar sizing and session isolation.

All runtime edits use the same asynchronous save path, including toggles, choices, sliders, colors, layout changes, resets, commands, and leaving edit mode. `settings_store` stages values in memory. `settings_writer` owns complete snapshots and coalesces queued changes for up to 150 ms before writing on its worker thread. Disk access never holds the runtime or writer queue lock. Unchanged values are skipped; existing INI sections, unknown keys, and comments are retained.

Settings loads and save comparisons fetch each Windows INI section once per operation through `settings_store::CachedFile`, avoiding thousands of individual profile API reads. Read caches remain separate from staged writes; each load or flush gets fresh file values. Windows retains parsing and encoding ownership, including case-insensitive names, first duplicate keys and quoted values. `/xiui startup` reports bounded timings for initialization phases, device setup, settings reload and the first HUD frame; the initialization total overlaps its component phases and excludes the host's full runtime swap.

Settings reload waits for pending writes before reading. Runtime state capture saves and drains the current snapshot before replacement, and shutdown drains and joins the worker before the DLL unloads. Failed saves retain their snapshot for the next save or explicit flush and report a chat message. A failed flush prevents runtime replacement or settings reload from discarding unsaved changes.

Config controls and movement reuse the same style. Native target/subtarget selection remains separate.
