# Module implementation reference

Feature details extracted from the shared foundations. Start with [the navigation guide](../README.md) for current task entry points and checks. Historical validation statements describe recorded sessions, not new acceptance evidence.

## Notifications

`notification_center` owns a bounded queue of typed events. It has no Ashita or rendering dependencies. Posts accept a monotonic timestamp, combine matching rewards within 350 ms, retain at most 32 entries, and expire by elapsed time. Messages can use `notification_kind::message`; numeric rewards use item, experience, or skill kinds with a stable key and amount.

Runtime event producers can call:

```cpp
runtime.PostNotification({notification_kind::item, itemId, count, itemName});
runtime.PostNotification({notification_kind::experience, 0, amount, "XP"});
runtime.PostNotification({notification_kind::skill, skillId, 0.3, skillName});
```

Call producers on the runtime callback path, which the host serializes. `notification_source` adapts Ashita packets and inventory state; `notification_renderer` only presents queue entries. Other producers can reuse the center without depending on the packet adapter. Packet producers also need their IDs in the host's `HandleIncomingPacket` forwarding list; the host forwards native, unblocked packets only.

Live sources:

- XP and limit points: incoming `0x02D` reward messages, filtered to the local player.
- Skill gains: incoming `0x029` message 38, converted from tenths. Names come from the SDK skill IDs, covering weapon, defensive, magic, automaton, and crafting skills. The separate integer-level message is ignored to avoid duplicates.
- Items: positive differences in settled totals across all inventory containers. Transfers between bags do not increase the total. `inventory_tracker` waits for the native container loading flags and incoming `0x01D` completion signals, then establishes a silent baseline after zoning, homepoint returns, logout, or inventory reloads. Loading has no time-based fallback. Normal update batches preserve the baseline so real gains still appear. Changes settle for 300 ms and are sampled at most twice per second; gains and losses within the same interval are netted.
- Gil: positive settled changes in native inventory slot zero; initial login and zoning balances are silent. The original gil icon uses the existing native item cache.
- Key items: newly set bits in native `0x055` key-item tables, compared against a settled SDK baseline. Duplicate updates, initial synchronization and removals are silent. Names come from `keyitems.names`.
- Invitations: native party/alliance `0x0DC` and trade `0x021` requests, with bounded names and validated entity identities.
- Treasure: new `0x0D2` entries that remain in the native treasure pool after 250 ms. Existing entries and items awarded immediately through `0x0D3` produce no duplicate pool alert.

Party/alliance invitations retain a visible row for the client's [90-second acceptance window](https://support.na.square-enix.com/faqarticle.php?id=20&kid=11265), with an `m:ss` countdown beside the sender. They remain stationary, take priority over regular rewards in the visible-row limit, and survive queue overflow. A new invitation replaces the previous one. The SDK pending-invite flag dismisses answered or canceled invitations after a brief packet-processing grace period; zoning/logout also clears them. All visible rows share the bottom row's rise offset so their spacing remains constant despite different ages. An active invitation pins that offset to zero; individual duration and fades remain independent.

The default presentation uses a stable screen-space anchor at 50% of the viewport width and 55% of its height. The visible notification stack is vertically centered there, with its right edge 72 pixels left of center before configured offsets, so longer rewards extend leftward. Player movement, world positions, and camera projection do not affect this anchor; first-person mode does not hide it. **Screen anchor** replaces **Follow player**, preserving its saved on/off preference. The retired X/Y offset sliders are no longer exposed; existing saved offsets remain effective for live anchoring so layouts do not shift. Turn it off to use the saved draggable position. Edit mode always displays samples. Normal animation never changes saved edit bounds.

Notification icons appear on the right of the text. Item, treasure and gil rewards retain their native item icons. Party/alliance invitations, trade requests and key items use the old XIUI renderer's exact `invite_icon.png`, `trade_icon.png` and `bazaar_icon.png` respectively, preserving their original colors and transparency. These unmodified 64-pixel assets are packed into one embedded atlas (resource 203) and loaded once per device by `ui::game_icon_cache`; no installed addon or per-frame image loading is required. The upstream license (resource 204) is retained in `assets/notifications` and seeded with the other notices. `scripts/build-notification-icons.py` rebuilds the atlas from the checked-in originals. Live and preview labels use **Party Invitation**, **Trade Request** and **Key Item**, retaining the sender or item details. `ui::game_icon_cache` lazily decodes Ashita's paletted item DIBs into managed Direct3D8 textures, retains up to 256 recently used entries, and clears on device/resource changes or shutdown. Modules share this cache through `module_render_context::Icons()`. Icons and text share layout and fade timing; an unavailable icon leaves the text visible without an empty gutter. Config's line symbols remain in the separate shared `ui::icon_atlas`, owned by the design system.

Queue contents are transient and clear on zone changes or runtime reloads. Preferences and positions persist in `xiuinative.ini`. `/xiui notify test`, `notify clear`, and `notify status` provide development controls without synthesizing game packets.

Notifications offers **Container background** in Appearance (off by default) and **Anchored direction** in Layout. Anchored right keeps the right text edge fixed, introduces text from the right and fades its native container toward the left; Anchored left mirrors this. Each row sizes to its icon and text, includes padding, and shares its arrival/expiry alpha with its container. The native nine-slice renderer applies one global horizontal alpha mask to the dark backing, tiled background, frame edges and corners. No opaque border is left at the transparent end. Text keeps its normal legibility and is not masked by the horizontal background gradient. Rendering creates no textures or offscreen targets. Notifications now has General, Events, Layout, Appearance and Animation topics. Events independently controls regular items, EXP/limit gains, skill gains, party/alliance invites, trade requests, key items, gil and treasure. Each type has its own color in Appearance. Older profiles inherit the previous Items switch for key items, gil and treasure and the previous item tint for the new color controls, preserving their existing presentation until edited. Container background is in Appearance; Anchored direction is in Layout. Layout also provides **Spacing**, a 0–64 pixel gap between notification rows. Its default is the previous four-pixel gap; `[notifications] row_spacing` persists through the shared writer. Live and edit previews use the same row pitch, including native container padding, and centered stacks account for the selected spacing.

Packet references: [XiPackets 0x02D](https://github.com/atom0s/XiPackets/tree/main/world/server/0x002D), [LandSandBoat battle-message packet](https://github.com/LandSandBoat/server/blob/base/src/map/packets/s2c/0x029_battle_message.cpp), and [message IDs](https://github.com/LandSandBoat/server/blob/base/src/map/enums/msg_basic.h).

## Inventory dots

Inventory is a native module with six independently movable storage trackers: Inventory, Satchel, Locker, Safe (1 and 2), Storage, and Wardrobes (1–8). Only Inventory starts enabled. Disabled trackers are also hidden in edit mode, including their movement outlines and pointer hit areas; enabling them restores their saved positions. The shared Inventory config category has Inventory, Equipment and Gil selectors. Within Inventory, a second selector chooses the storage tracker, with General, Layout, Fullness, Appearance, and Text topics. Safe and Wardrobes can show combined totals or separate grids stacked within their tracker. Locked containers are omitted. `/xiui inventory` opens these settings; `/xiui inventory status` reports occupied slots, actual capacity and readiness without item contents.

`inventory_source` reads the SDK's container slot counts and capacities at most twice per second. Stack quantities do not affect slot fullness. Per-container native loading flags, inventory completion packets and login/zoning state gate readiness. Zoning clears the previous snapshot immediately; ordinary item-update batches retain the last ready counts until completion, avoiding empty-grid flashes. Loading has no timer fallback.

Each slot has one dot. Occupied dots use the shared accent by default, empty dots keep their muted tint, and configurable warning/critical colors apply at inclusive fullness thresholds. Percent full defaults to 75/95; fixed Used slots mode retains XIUI's per-storage threshold defaults. Full storage is always critical. Threshold units, colors, count/free-slot presentation, labels, dots, row/column grouping, actual pixel diameter, spacing, and above/below text are independent per tracker. Groups wrap at the viewport width without dropping slots. Counts optionally use `TintTextProfile` to retain configured gradients and text effects. Label/count profiles use the shared controls and persistence. The optional background uses the shared native DAT container and dark backing.

`design_system::DrawSlotDots` draws smooth beveled dots from one generated 64-pixel managed mask, created once per device and released with the other renderer resources. Up to 256 dots share each triangle-list draw; drawing performs no asset reads, texture uploads or heap allocations. `xiui_inventory_smoke` covers native slot/loading data, locked storage, combined totals, fullness boundaries, wrapped grouping, separate-grid sizing, settings/text/color persistence, and config ownership.

## Equipment

Native item bitmaps include their quality borders, including white HQ and blue upgraded borders. Keep the complete bitmap and UV range; do not infer borders from item names, rarity flags or augments. Decorative **Slot frames** are independent of those bitmap borders. Client samples Haubergeon/Haubergeon +1 (12555/13735), Warrior's Lorica +2 (10670) and Dusk Gloves +1 (14825) confirmed the artwork path on October 15.

Equipment is an independently movable native module with all sixteen slots in the game's standard grid order. It starts enabled in a 4-by-4 layout; 8-by-2 and 2-by-8 layouts, exact icon size, slot spacing, icon padding, heading, slot labels, empty labels and ammunition counts have independent config controls. The outer window and optional slot frames use the shared native DAT container. Icons use `module_render_context::Icons()` and the existing bounded item-icon cache, with no downloaded or bundled item artwork.

`equipment_source` samples the SDK equipment entries at most every 100 ms, resolving each packed index into its real container and slot. Inventory and all Wardrobes use the same path. Invalid indexes, loading containers, empty item records and sentinel IDs do not replace a ready slot with an empty icon. An actual unequip clears that slot. Inventory session readiness and zoning/logout packets clear stale equipment. Native item names are converted to UTF-8 and cached when the item ID changes.

Hover tooltips show the item name, equipment slot and bag through shared HUD text profiles and containers. They render after configuration, stay inside the viewport, and yield to config/color-editor hover regions. Hovering never captures keyboard or mouse input. Heading, label, ammo and tooltip profiles retain shared text effects and persistence. `/xiui equipment` (or `/xiui gear`) opens settings; `/xiui equipment status` reports source readiness and equipped-slot counts. The focused `xiui_inventory_smoke` target also checks equipment bag/index resolution, ammo, empty/loading/invalid slots, native grid order, layout bounds, settings and Extras routing.

## Gil

Gil is an independently movable module, enabled by default. The balance comes from native inventory container 0, slot 0, item ID 65535. Its icon is the original Gil DAT bitmap supplied by Ashita's resource manager and rendered through the shared item-icon cache. No copied addon artwork is bundled. `/xiui gil` opens General, Layout, Appearance and Text settings; `/xiui gil status` reports the current balance, earnings, readiness and native icon availability.

The optional second line shows signed session net or net gil per hour, including spending. Native inventory loading flags, completion packets and login/zoning state gate sampling at most twice per second. A ready zero balance is valid. Zoning retains the baseline; login and character changes start a new session. The shared Reset action or `/xiui gil reset` starts from the current balance. Hourly display updates every three seconds. `[session.gil]` preserves the baseline and monotonic start across development runtime replacement, guarded by process ID, process creation time and character ID; another client process cannot restore it.

Icon visibility, side, size, alignment, line spacing, optional native container, positive/negative tints, and independent balance/tracking text profiles persist through the shared writer. Tracking uses `TintTextProfile` so gradients and text effects survive. `xiui_inventory_smoke --gil-party-only [AgentLink gil DIB]` checks balances, readiness, signs, rates, resets, session restoration, original-icon decoding, config actions, and alliance preference copying.

Each alliance's General settings include **Hide in preview**. Hidden previews render no panel or edit outline and capture no pointer input; normal alliance visibility is independent. `/xiui party copy-alliance` copies current Party presentation and layout preferences to both alliance modules while retaining their identities, positions, enabled states and preview visibility. This is an explicit copy rather than ongoing synchronization, so later alliance customizations remain independent.

## Satchel inventories

Satchel is a separate registered inventory browser; capacity trackers, Equipment and Gil keep their own settings and positions. It shares native item icons, containers, text roles, focus frames, configuration text and common visibility. All item-changing routes call `satchel_actions` with a captured identity and revalidate against the SDK before sending. Read-only cached/slip records cannot dispatch. See [Satchel](../satchel.md) for commands, input and supported item details.

`satchel_source` retains complete native extra data and per-item generations; `satchel_cache` observes settled records only. Each local character cache uses its own `settings_writer` and `settings_store::AtomicFile`, which writes a complete adjacent temporary file, flushes it and replaces the destination atomically. These observation/layout files stay outside portable HUD profiles. Unknown/truncated storage-slip data remains unavailable; all 28 known catalogs are embedded with MIT attribution.

## Player resources and MP preview

**Player Bar → General → HP values / MP values** offers Number, Percent, Number (percent), Percent (number), Current / max and Hidden. Local native maxima supply the formats; zero/unknown maxima are handled explicitly. **Text** has independent HP/MP/TP label and value profiles. Existing labels/values remain HP's saved keys; `player.resource_text_version` seeds new MP/TP profiles once from the fully loaded legacy profiles, including fonts, gradients, effects, placement and offsets.

Player and Party share local resource samples. Native percentages validate reported maxima, rejecting stale totals after a job change. A native 100% sample establishes the exact total; it remains usable after damage/spending while consistent with subsequent percentages and the same job/level. Character, zone and job changes invalidate that retained total. Until an exact maximum is available, Player fill and percentage text follow the native percentage, Current / max shows `?`, and MP cost segments remain hidden. Estimates are never presented as exact Player totals.

Player, Pet, Party and both alliances share native HP value colors through `ui::HPValueColor`: below 75% yellow, below 50% orange and below 25% red. At 75% and above the normal text profile is retained. These tints use the current native percentage, independently of fill animation, damage/healing effects and HP bar-color preferences. Only HP values are tinted; MP, TP and unavailable pet placeholders keep their own styles. `TintTextProfile` preserves gradients, alpha, effects, offsets and placement.

**Player Bar → Colors** retains opt-in HP fill colors with inclusive custom warning/critical thresholds and separate gradients. **Custom HP text tint** explicitly overrides the native value tint with those custom fill colors when enabled. It also controls TP-ready text tint, an optional upper-stage overlay gradient and blink color/alpha. Three-stage TP fills remain intact; state tints use `TintTextProfile` and never overwrite saved text styles. Large or offset resource text contributes its measured footprint.

**Player Bar → General → Spell MP cost preview** and **Party → Resources → Spell MP cost preview** are independent switches, both enabled by default. Each controls only its own display and works with Cast Cost hidden. Party previews affect only the actual local member. The switches persist in `[player] mp_cost_preview` and the selected Party list's `mp_cost_preview`; the former global Resources setting is no longer used. It reuses `cast_cost_source` and the native selected-spell resource's base `ManaCost`; cost modifiers are unavailable and are not estimated. The overlay spans remaining-to-current MP using the exact MP maximum, with separate affordable/insufficient treatment, clipped to the themed/Modern meter fill. Native menu close, zoning/session/job changes and stale samples clear the selection. Zero cost remains a valid selection with no segment. Party previews and remote/estimated MP maxima never receive a fabricated overlay.

## Player casting and action cost

Casting is one sidebar category with Cast Bar and Cast Cost settings selectors. The two HUD modules retain independent enable states, bounds, meters, text profiles and persistence. The category remains visible while either module is enabled. `/xiui casting` opens Casting; `/xiui castbar` and `/xiui castcost` open their respective settings within it; each has a `status` command for live source diagnostics. Both use the shared bar topics, native/Modern meter renderer and HUD text controls. Edit mode supplies samples without affecting game actions. No action-selection or cast-state memory is written.

`player_cast_source` filters incoming action packets to the local player. Spell/item start packets provide the resource name, completion packets clear the cast, and interruption packets freeze its last progress for 700 ms. Progress comes from the SDK `ICastBar` getters, including native type and count validation, rather than a duration estimate or guessed Fast Cast correction; see the [Ashita cast-bar structure](https://github.com/AshitaXI/Ashita-v4beta/blob/main/plugins/sdk/ffxi/castbar.h). New casts reject unchanged previous-cast samples. Invalid/stalled progress expires after 1.5 seconds, with an independent hard lifetime bound. Death, logout, zoning and character changes clear transient state. Item use and interruption display are independently configurable. Name and percentage use the shared inset bottom-edge meter layout, gradients and effects. Interruption text uses `TintTextProfile`.

`cast_cost_source` samples native magic, ability and mount menu selections at most every 50 ms. Signature scans occur once at initialization. Menu/global pointers use guarded reads; closed/unrelated menus, invalid indexes, empty lists, unavailable resources and unsupported signatures produce no selection. Native list-item methods are resolved from the original XIUI signatures, checked for expected match counts and called behind bounds checks and structured exception handling. They only read the highlighted action; the game retains menu actions and targeting. `/xiui castcost status` reports the supported menu types.

Cost rows show the resource MP/TP requirement and use a state tint when it is insufficient. Weapon skills require at least 1000 TP and also show current TP. Base spell cast/recast times come from resource quarter-seconds; they do not include equipment or buff adjustments. Live spell and ability recasts use SDK timers in sixtieths of a second, with abilities matched by shared timer ID. Mounts use the native mount timer. Ready, Quick Draw and level-scaled Stratagem pools show available/required charges and the next-charge cooldown, including native recast modifiers. An available charge can remain ready while another recharges. Missing recast data is identified rather than treated as ready. The optional container uses the shared native DAT renderer. Five independent text profiles retain normal HUD effects.

Player's **General → Auto-hide MP** defaults on for new and existing profiles without the new key. Zero maximum/current MP hides the MP meter and gives HP/TP equal columns with the normal gap; zero current MP with a positive maximum retains all three columns. The existing MP colors, text, styles and selected editor remain saved. Turning the preference off restores three columns. `[player] hide_zero_mp` persists through the normal writer, without changing captured defaults or other saved preferences.

`xiui_casting_smoke` checks native cast transitions, interruption/expiry, local action filtering, guarded menu selection and closed/invalid lists, resource readiness, charge arithmetic, independent config/persistence and the two/three-column Player layout. It does not launch the game or inspect rendering.

## Recast

Casting includes Cast Bar, Cast Cost and **Recast** as independent modules. Recast offers **Bars + icons** and **Text only** displays in the same settings panel. It uses the normal shared meter and text profiles, preserving gradients, shadows, strokes, glow and offsets; numeric countdowns use transient tabular digits. Text-only mode omits both bars and icons without changing their saved preferences. General controls spell/ability visibility, charge counts, heading, countdown precision, optional native container and a configurable Ready display (zero hides completed timers immediately). Layout controls width, maximum rows, row height/spacing, icon size, sorting, left/right anchoring and filling toward readiness or draining toward readiness. Colors has independent cooldown, approaching and ready gradients, configurable second thresholds, and smooth, stepped or fixed transitions. Names and countdowns default to white, with normal text effects and opacity. Version 1 disables the earlier default tint once; later color choices remain intact. Optional text tint uses `TintTextProfile`.

`modules/recast/recast_source` samples Ashita's 32 ability slots and 1,024 spell timers every 250 ms. The tracker deduplicates ability recast groups, retains observed full durations per cycle, interpolates between native samples, and only declares Ready after a sample confirms completion or reset. Cast Cost, Recast and Action Bars share the independent `combat/ability_recast` metadata and boundary-safe calculation for Ready, Quick Draw and Stratagems, displaying current/maximum charges and the next-charge countdown. Signed `Calc2` correction stays in that shared calculation; Sic remains an ordinary cooldown when Ready is unavailable. Job-specific one-hour names follow the current main job. Logout, zoning and job/character changes clear stale data. Loading the module while cooldowns are active discovers them from memory; an ordinary timer loaded partway through a cycle uses its first observed remaining time as its initial bar duration. Cooldown progress follows native time directly rather than adding resource-bar smoothing.

Recast action artwork is stored under `assets/recast/icons`. `scripts/build-recast-icons.py` packs it into one atlas with extruded edges and generates the sorted spell/timer/job lookup. The shared game icon cache uploads this embedded atlas once per device; drawing performs no file reads or texture creation. Unknown artwork uses shared casting symbols. Preferences, positions and shared profiles persist under `recast`, `layout.recast`, `meter.recast` and `text.recast.*`, including profile sharing/import. `/xiui recast` opens settings; `/xiui recast status` reports the native source, tracked timer count and embedded artwork. `xiui_casting_smoke --recast-only` covers timer cycles, duplicate IDs, charge boundaries, Ready retention, fill anchors, color changes, artwork lookup, text-only layout, settings and Casting routing.

## Enemy list

Each enemy draws its own native DAT container through `module_render_context::DrawContainer`. There is no outer background around the stack. The module reuses meter styles, text profiles, configuration controls, persistence, and the normal edit outline/dragging system. Empty lists hide automatically; edit mode supplies three sample cards.

`enemy_source` polls live entity state at most five times per second and listens to incoming action packets. Party/alliance claims and enemies acting against group members or their pets establish tracking. Friendly allies, dead/despawned entities, reused indices, and other groups' unrelated enemies are excluded. Entries retain encounter order, cap at 32, and drop unclaimed stale enemies after 30 seconds. Zoning, logout, and changing characters clear tracking. Selection updates each frame for the optional selected-enemy inclusion. No native HUD window is required.

`combat/action_packet.hpp` provides a bounds-checked action decoder, including all targets and optional additional/spikes blocks. Cast names and base spell timings come from game resources; monster ability readiness uses a three-second estimate. Completion/interruption packets and expiry remove stale casts. The enemy target line shows its last action recipient, expiring after 30 seconds.

Open `/xiui enemylist` for preview and settings: rows/columns, spacing, width, padding, opacity, entry/claim borders, click targeting and independently positioned target panels. **Include selected** optionally includes an unclaimed selected enemy. Rendering, editing, clicks and controller browsing use the same measured grid; narrow viewports can reduce columns. Settings are stored in `[enemylist]`, `[layout.enemylist]`, and their meter/text sections. See [P15](../implementation/15-enemy-list-layout.md). The host forwards action packet `0x028` through the existing packet callback.

Enemy cards default to 220 pixels wide, 6 pixels of inner padding, and 6 pixels between cards. Enemy names and their targets share the header above the HP bar, with targets on the right. Both names shorten within separate bounds; the target uses at most 45% of the available width. Distance and HP percentage share the HP bar's inset lower row through the same meter text layout as Target. An optional cast row follows when present. Selection adds no arrow or name indentation. Existing default dimensions migrate once to the compact layout.

Target and enemy names share `entities/entity_name_colors.hpp`: unclaimed monsters are yellow, group claims red, other claims purple, NPCs/allies green, group members cyan, and other players white. Explicit native name-color entries take precedence. Claims compare the low-word server ID, excluding the native high-word flag. Names update from entity state without native HUD windows; edit samples show the three claim states.

The Target module also uses entity type to suppress its entire HP row for NPCs and scenery, retaining the name and optional distance. Players, monsters, and friendly combatants keep health displays. This presentation does not depend on the native target window being enabled.

Target Bar has sibling **Target** and **Target of Target** categories in the full-width top row. Target keeps its normal topics; Target of Target has General, Layout, Bar Style, Animation, Effects, Colors and Text in the secondary menu, using shared navigation and input geometry. The former nested side-menu entry and extra horizontal topic row are removed. Its classic XIUI default places a one-third-width HP bar to the right of the main target, with the original arrow and both HP bars vertically centered. Name and HP are shown by default; percent/HP label/distance/cast/status/timing are optional. Inline left, Below and Above layouts, top/center/bottom HP alignment, independent width/height/spacing/X/Y, arrow visibility/size/gap/offset/color and name above/inside/below are configurable. Text has four independent shared text profiles (Name, Distance, HP label and HP value), each with its own native Size (px), font, effects and offsets, plus an optional follow-target switch and game-state tinting. The former all-text multiplier migrates once into these profile sizes, copying inherited profiles when needed to retain their displayed appearance. Meter style/animation/effects and fill colors can follow Target Bar or use independent settings. Bar Style, Animation and Effects each expose the shared Follow target style switch to unlock their independent controls. Preferences live in `[target.target_of_target]`, `meter.target.recipient` and `text.target.recipient.*`; the edit preview supplies a recipient when unavailable. Version 1 migrates untouched earlier defaults to the inline presentation once and preserves customized earlier geometry as Below. Original `assets/icons/target-arrow.png` is baked into the shared icon atlas by `scripts/build-target-arrow.py`; Arrows appear only for Inline right and Inline left; Above and Below reserve no arrow space. Inline left mirrors the original arrow horizontally, retaining its upright artwork and shadow. Arrow controls are disabled for stacked layouts without changing their saved preferences. Mirroring uses atlas UVs with no runtime file reads. `xiui_config_input_smoke --target-recipient-only` checks classic geometry, alignment, topic routing, styled persistence and migration. Target shows its observed action recipient (target-of-target), the native secondary subtarget while subtargeting, cast progress and status icons within the existing module. Extra rows extend its content/edit footprint without replacing saved width, text profiles or meter settings. Native lock-on adds a themed selection frame around HP. Friendly local-party status snapshots are authoritative, including empty snapshots; enemy and other-target effects use the shared `combat_source`. Target and Enemy List reuse cached native status icons and shared text effects.

`combat_source` retains bounded action results and confirmed status gain/removal evidence from `0x028`/`0x029`. It keeps at most 128 entities and 32 effects per entity and clears on zoning/logout/character changes. The retained original XIUI database in `assets/status` is the primary duration catalog for combat observations; `scripts/build-status-rules.py` imports fixed spell/ability/weapon/pet/proc durations and per-effect overrides into an embedded native table. `combat_status::estimated` marks these deadlines, shared labels show plain countdown numbers, and a smaller hover-tooltip note says "Estimate: Effects may end early". Resists, no-effect messages and damage alone do not start or refresh effects. Observed wear-off/removal/death clears them immediately; estimated expiry also removes tracked icons. Unknown catalog entries stay untimed. Gear/merit/JP/TP formulas and unconfirmed secondary-effect inference are excluded. Actual local native deadlines and authoritative local/party presence stay separate. Cast progress remains a separate estimate. `/xiui features status` reports live tracking counts. `xiui_module_parity_smoke --status-timers-only` checks lookup, namespaces/overrides, labels, early removal, refresh and expiry.

`party_source` pairs local `IPlayer::GetStatusIcons/GetStatusTimers` with the validated client UTC clock. Native hidden/unavailable/expired timers remain untimed. Other party members provide authoritative IDs without expiration times. Target prefers these snapshots, including known empty lists. `ui/status_strip.hpp` shares status layout, countdowns, hit testing and native descriptions; `ui/status_classification.hpp` supplies effect-ID grouping without treating cancelability as polarity. Party supports native order, buffs/debuffs first and independently configured split rows. The registered Buffs/Debuffs modules reuse the local source, normal movement/text/persistence and shared visibility. See [Status Effects](../status-effects.md) and [native-data research](../native-mob-data-findings.md).

**General → Visibility** owns global and per-module event/menu policies, macro-palette exceptions, alliance-only menu hiding and Player hide-in-party. Its **Hide all UI** action and `/xiui hide` temporarily hide XIUI and the supported native HUD together. `/xiui show` restores XIUI and the saved native choices; `/xiui toggleui` toggles both. Global hiding exits edit mode, releases input focus and preserves module switches, native preferences and layouts. Runtime hot reload retains this visibility state through the existing state transfer. Legacy Party/Inventory/Gil flags migrate into the shared settings. Runtime rendering, tooltips and input ownership consult the same context; editing retains previews for enabled modules. Disabled modules have no preview, edit frame, drag hitbox, snap target or movement toolbar, while their settings remain accessible. Hidden surfaces release pointer/controller ownership while sources keep updating. See [P21](../implementation/21-shared-visibility-rules.md).

Outside edit mode, party/alliance and enemy entries support click targeting through the SDK's native `SetTarget(index, false)`. Hits use actual row geometry and reject headings, row gaps, other-zone members, replaced entities, hidden lists, game-owned clicks and ordinary native menus. Chat retains input priority. Only the matching left-button gesture is consumed; right-button camera movement, keyboard movement and Escape remain with the game. Editing retains normal module dragging.

Player Bar integrates [Cadence's attack and resting behavior](https://github.com/KiplingFFXI/cadence/tree/f04cdcc0162b4d7ba9c2e8dc3cebd1528a4d8de0) through independently implemented native C++ timing models. **Attack Timing** adds an auto-attack countdown, TP goals of 1000/2000/3000, rounds, successful hits and optional time to goal. **Recovery** adds resting ticks, last HP/MP gains, a percentage recovery goal, combined or separate HP/MP estimates, hide-when-full and an optional full-recovery sound. Player timers default on; the sound defaults off. The sound dropdown reuses the existing native/ChatMon choices and supports the normal preview buttons. The trackers use the existing Player module rather than adding sidebar entries.
