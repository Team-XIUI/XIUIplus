# Target Rings

Implemented October 15, 2026. The former **Target Bar** category is now **Target**; existing settings and positions keep their `target` identifiers.

Open **Target → Target Rings**. Rings start enabled for the selected living monster, with a band matching its current name/claim color, thin inner/outer rims, soft edge glow and a triangle that marks the enemy's front and points along its native facing direction. They follow native target position and the world camera without affecting the normal Target window or its edit bounds.

- **General:** Enabled, HP fill, Show for NPCs and Show for players. NPC/player rings start off; enable each independently. NPCs without a health resource receive a full decorative band. HP fill smoothly interpolates toward the client's actual enemy HP percentage for both damage and healing; disable it for a complete decorative band. New targets start at their own current HP without carrying over the previous target's fill.
- **Layout:** Inner radius and Outer radius, side by side, in world units (yalms). The defaults are 1.15 and 1.40. Changing either keeps the outer radius greater than the inner radius.
- **Colors:** Follow target name color starts on and reuses the shared native name/claim colors, including configured entity-name overrides. The ring, triangle, trim and glow update as claim/name state changes. Ring color retains its opacity in either mode; its custom RGB applies with Follow target name color off.

The renderer reads installed zone DAT geometry in the background, using the terrain decoding already used by PhoenixLighting. It clips each part of the ring onto actual floor triangles, preserving slopes and separate stair levels. Nearby overlapping floors select the surface closest to the target's native ground height. Missing surfaces remain gaps; there is no invented flat-plane fallback. Cutout foliage, blended effects, walls and authored moving objects are excluded. This first version supports static zone floors; moving elevators/platforms are not mapped.

The ring uses the actual world scene surface, authoritative terrain camera and matching depth buffer, including clients that render the world offscreen before copying it to the back buffer. It draws at the verified scene-copy boundary after the remaining world passes; early screen labels are not treated as the end of world rendering. The draw scope unbinds all eight texture stages before temporarily binding the retained scene surfaces, then restores the interrupted copy's targets, all texture bindings, native vertex/index buffers, transforms and viewport. Depth writes remain disabled. The host observes native draws before replacement renderers such as PhoenixLighting consume them. Terrain stays in memory for the current zone; the mesh rebuilds only when the target, position, facing, animated HP fill or appearance changes. Zoning, hidden/unrendered entities, dead health-bearing targets and unavailable terrain draw nothing. Target's enabled and contextual visibility controls also apply.

Settings use ordinary mouse, keyboard and controller controls. The ring is a passive world display and captures no targeting or movement input. Preferences persist in `[target.rings]` and participate in global defaults, reset and profiles.

Ring placement uses the native model draw's interpolated root position, which can differ from the entity movement coordinates while walking. `world/entity_render_position.hpp` verifies the actor/entity ownership and the client position getter before reading its vector; unavailable layouts hide the ring. There is no velocity offset or additional position smoothing. The focused ring check covers a movement anchor ahead of the rendered model, actor replacement and invalid native layouts/coordinates.

The host/runtime contract is **ABI 16**, carrying the world draw callback and borrowed scene color/depth surfaces alongside the captured camera/viewport. Development installs must replace both DLLs together once; the standalone distribution remains one DLL.

Focused verification: `xiui_config_input_smoke --target-rings-only` covers slope vertices, separate steps, stacked floors, HP arcs, missing geometry, radius constraints, config ownership and preference persistence. An optional client-directory argument also decodes Jugner Forest and projects onto a known native floor position. Cody checks the visual/gameplay result.

Temporary depth-disable probes were removed.

Motion fix: capture the camera on actual world draws and project the terrain-clipped vertices directly into scene coordinates each frame, retaining depth and reciprocal W. Near/side/far clipping prevents projection spikes. This avoids inheriting fixed-function transform state from another native draw. The initial 20-frame check did not catch the remaining slope artifacts.

Depth testing stays enabled and floor geometry and ring XY positions are retained.
