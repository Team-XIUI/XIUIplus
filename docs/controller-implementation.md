# Controller implementation

The first controller milestone implements XIUI input ownership, navigation and hybrid chat composition. The broader [controller plan](controller-plan.md) still includes native software-keyboard integration and physical-device acceptance checks.

ABI 18 separates native macro suppression from crossbar activation. **Replace native macros** defaults on: the host blocks the native macro-start entry, hides its palettes and filters configured native trigger buttons, even with an inactive or unconfigured crossbar. Explicit XIUI-macro actions use a host callback to the original runner. Replacement can be disabled through Action Bars; held keys and triggers drain through release. The selective controller filter supports mapped DirectInput buttons and XInput triggers/buttons; the native execution guard also covers starts through unsupported trigger-axis mappings. See [Action Bars](actionbars.md).

## Entering XIUI

**General → Visibility → Hide all UI** uses the same red warning action for pointer and controller input. Its confirmation starts on Cancel and includes recovery instructions; held Confirm cannot accept it. Explicit Hide all hides XIUI and the native HUD, exits configuration and releases focus. `/xiui show` restores the previous visibility choices, and `/xiui toggleui` is available for a user-assigned macro or binding.

**Party → General** exposes Classic and XIV through two boxes side by side using shared actions. Each opens the shared themed warning with Cancel selected. Keyboard/controller navigation selects Cancel or Apply; only explicit Apply replaces the custom appearance settings of Party and both Alliance lists, retaining their positions. Cancel, Escape, closing configuration or reloading cancels the pending action, and held Confirm cannot repeat it. All devices call the same preset action; normal settings and profiles retain the result. The three-dot menu's **Reset to defaults** opens a separate Cancel-first warning. Explicit Reset restores the entire XIUI configuration and positions from any category through the same mouse, keyboard and controller action. Disabled Delete on the Default profile is skipped without hiding Reset; held Confirm cannot apply it repeatedly.

Press the mapped Select Active Window button (**Y / Triangle** with standard bindings) to enter and cycle **Chat 1 → Chat 2 → Buffs → Debuffs**, skipping disabled/context-hidden chat and disabled or empty effect groups. Keyboard **F** also enters this cycle in Compact 1 and Compact 2. Full mode leaves an unfocused F available for typing; F still navigates after explicit chat/status focus. Status selection uses XIUI's own icons, focus frame and tooltip; directions inspect effects and Cancel/Escape releases focus. With Chat 2 disabled, F from focused Chat 1 selects Buffs when effects are available. **Confirm (A / Cross)** or **Enter** expands a selected chat window; the cycle button or F then changes its channel tabs. Cancel/Escape backs out one layer: expanded history returns to the same compact chat window with focus retained, and a second fresh press leaves chat focus. Native text entry, spell/ability subtargeting, cutscenes and existing XIUI interactions retain their own controls.

Use `/xiui focus` to open the picker for other XIUI areas, or bind that command using your existing command/macro setup. Direct entry is available through `/xiui focus chat|chat2|party|enemies|target|buffs|debuffs|pet|equipment|readycheck|config`; `/xiui focus off` releases focus outside configuration.

Satchel is also available in the picker and through `/xiui focus satchel`. Grid navigation across pages, the left bag menu, profile dropdown, slip picker, search, help and item dialogs share keyboard/controller operations. Compact windows scroll focused bags/slips into view and show synchronized item-page and sidebar scrollbars. Minimize/restore is a shared title-bar action; collapsed navigation skips hidden contents, and Ctrl+F restores search. Focus the title bar or bottom-right grip and Confirm to move/resize with directions; Confirm saves and Cancel restores the starting layout. Display order remains in configuration. Drop starts on Cancel and requires a fresh activation; repeated Confirm cannot accept it. Cached/slip targets stay read only. Native menus/text/targeting, zoning, hidden UI and foreground loss suspend browsing, cancel unfinished layout gestures and drain owned releases. Search uses keyboard text entry; physical-controller acceptance remains with Cody. See [Satchel](satchel.md).

Treasure Pool joins the picker while a ready, visible pool contains items; `/xiui focus treasure` enters directly and can be bound to a macro. Automatic appearance never steals focus. Up/Down changes item rows or reaches the footer, retaining the same action where available; Left/Right moves between details/Lot/Pass or footer controls and skips unavailable actions. Confirm activates once, Actions toggles lot history, and Cancel leaves focus. Lot All/Pass All revalidate captured identities; held Confirm cannot repeat requests. Native menus/text/subtargets, zoning, foreground loss and hidden/empty UI release browsing. Mouse and keyboard share these operations. Alerts remain in Notifications. See [Treasure Pool](implementation/07-treasure-pool.md); physical acceptance remains with Cody.

Party **Next tab** opens the focused member's status details; **Actions** retains Tell. Enemy List **Actions** opens its focused enemy's effects. Dedicated Target, Buffs and Debuffs focus surfaces inspect available icons directly. Directions move between effects and Cancel returns to the row or exits standalone inspection. Native effect names/descriptions appear in the final tooltip overlay. Removed effects and context-hidden modules release inspection; viewing details never targets or cancels an effect. See [Status Effects](status-effects.md).

Pet focus inspects confirmed visible pet effects, using pet generation plus effect identity to survive ordinary updates and release on replacement/loss. Mob information is passive content within Target, controlled through Target → Mob Info with shared configuration navigation. Its Common/per-group tabs use the shared element selector; optional independent groups reuse Movement, snap and centering, and leave Movement when hidden or data is unavailable. World Target Bar and Target Rings use ordinary Target configuration and add no world input capture. Ring enable/HP toggles, paired radii and color/opacity use shared controller controls. Neither display has a separate browsing-focus surface, queries the server or changes native targeting.

From gameplay, **D-pad Up/Down** stays with FFXI's native party/alliance targeting. XIUI does not intercept those presses or open its separate party browser. To browse XIUI rows deliberately, use the focus picker or `/xiui focus party`. Within that browser, Up/Down cycles members, Left/Right changes visible groups, **A / Cross** targets the highlighted member, **B / Circle** leaves browsing, and **Y / Triangle** switches to visible chat. Chat, config, native menus and spell/ability targeting keep their own D-pad controls.

Chat focus and expanded history capture navigation controls while leaving movement/camera sticks and unrelated keyboard movement available. Typing still owns keyboard text input. Configuration and modal controls retain exclusive capture. Party browsing yields immediately to the live native menu-input flag, including the main menu, inventory and equipment; it does not rely only on the movable command-panel snapshot. Its focused row uses the shared antialiased border overlay, with no bottom helper window. The overlay is drawn after HUD contents, including out-of-zone panels.

The config title bar offers Auto, Keyboard & Mouse and Controller presentation. General → Input shows the configured backend, gamepad configuration, Ashita enumeration, connection observations, mapping availability and recent input. `/xiui controller status` prints a compact diagnostic; `/xiui controller` opens those settings. Presentation preferences persist without moving the HUD or changing Windows/FFXI/Ashita device settings.

Confirm, Cancel, Actions, Cycle Window and navigation follow the effective native mapping. Focused chat uses the native left/right macro triggers for Previous/Next tab, leaving both bumpers available for auto-run and other native actions. Configuration and other exclusive surfaces retain shoulder buttons. Tab bindings yield to mapped core actions. The crossbar uses the original Lua controller artwork with mapped prompts, trigger badges, press feedback and bank transitions; configuration prompts retain neutral action names.

## Implemented paths

Action Bars **Keybinds** opens an independent slot list from Hotbars → Actions, Crossbar → General, the bar menu or `/xiui keybinds`. Confirm on a hotbar binding starts explicit keyboard combination capture; Escape/Cancel abandons it. Crossbar rows use the shared XInput/DirectInput mapping dropdown with Auto/Unbound choices; mappings apply across trigger banks. Directions scroll through slot rows, Left/Right reaches Clear, and Cancel dismisses the current dropdown/capture before closing the window. Holding Confirm cannot repeat a binding change or execute an action. Controller navigation can choose keyboard bindings, but supplying a keyboard combination still requires the keyboard. See [Action Bars](actionbars.md#keybinds).

Configuration uses the shared [settings order and paired rows](settings-organization.md). Controller focus follows displayed geometry rather than assuming every row has two available controls. Empty cells and disabled controls are skipped; scrolling and pointer input use the same slots and original option IDs.

Player resource formats, state colors and separate resource text use those same controls. Player Bar → General and Party → Resources each have a passive MP preview preference, enabled by default and independently adjustable. Target's Subtarget and Target of Target views expose independent settings; Independent/Detached windows join Movement Preview with normal centering, Confirm/Cancel and committed-position autosave. FFXI retains subtarget and spell confirmation. Detached status icons share Target effect inspection, including when main Target is disabled.

Long configuration pages show a scrollbar synchronized with controller focus scrolling and pointer/wheel input. Native Chat Filters and Log routing use the shared dropdown/toggle controls, with unavailable client settings disabled. Selecting their group changes the visible controls without changing game settings.

Chat and Chat 2's Animation topic uses the shared dropdown for Off, Fade + slide up and Fade + slide right, plus the shared slider for Animation speed (%). 100% retains the original speed; higher is faster. These change only new-message presentation; controller history focus, scroll positions, composition/caret behavior and native ownership use their existing paths. Expanded/scrolled history stays static.

Profile deletion starts on Cancel and requires a separate activation.
- Configuration resizing: Utilities → Resize uses directions for size, Actions for one-pixel steps, Confirm to save and Cancel to restore. See [Configuration window](config-window.md).
- Configuration sidebar: Utilities offers Collapse sidebar to icons / Expand sidebar, sharing the top-left arrow's action. Category focus retains name help in the compact strip; profile controls remain available, and content reflow keeps stable setting focus. The preference persists with the configuration layout.
- Settings search: Utilities → Search expands the header icon into the search field. Keyboard input supplies the query; Up/Down selects results, Left/Right pages, Confirm opens, Actions clears the query and Cancel closes. Mouse clicks and Enter share the same category/topic/element navigation without applying the control. The header input-mode button uses keyboard/controller artwork, with full names retained in its menu.
- Movement: the selected element's name, coordinates and mouse centering icons sit in a compact strip anchored at the top center. The Movement Preview region lists enabled, editable modules. Confirm starts Move mode; directions nudge by the grid snap amount, Actions switches to a one-pixel fine step, and Next/Previous tab centers X/Y. Confirm saves, Cancel restores the pre-move bounds. Other automatic saves retain the committed position while the preview is active. Party/alliance placement can reach the screen edge without reserving outside ticker labels or edit padding, using the same bounds as mouse movement.
- Per-character profiles reuse the existing profile controls. Character changes cancel confirmations and transient focus while retaining unsent chat, then restore the locally bound shared profile. Unknown identity and failed automatic loads pause profile autosaving. No controller bindings or hardware settings change.
- Chat history: Confirm expands/compacts, Cancel backs out one layer, Cycle Window/Next/Previous tab changes filters, Up/Down moves one message and Left/Right pages. Window 2 retains its own filter and scroll state.
- Reactive chat: active history and composition hold the full window open. Compact rendering, pointer hits and controller focus use the same current frame, including optional shared-stack displacement. Saved positions and drafts remain intact. See [Chat windows](chat-windows.md).
- Chat composition: Actions enters the existing editor with Channel / Send / Back actions. Keyboard input supplies text; one fresh activation of Send uses existing validation and submission. Drafts, recipients and the originating history window survive cancellation. Opening history never sends a draft.
- Party: gameplay Up/Down remains native targeting. Explicit XIUI party focus uses Up/Down to browse visible members and Left/Right to change groups. Out-of-zone members can be inspected without pretending they are targetable.
- Enemy List: Up/Down browses visible enemies; Confirm shares the normal validated target action. Focus follows server ID plus entity index across row changes and ends if the entry disappears.
- World Info: Layout offers Stacked, Single row and Independent. Independent Time, Weekday, Weather and Date use the shared mouse/controller movement actions, with separate saved positions and widths. Move element selects the movement toolbar target; disabled pieces leave Movement and edit previews.

- Pet/Pet Target: category settings and independent target movement use the shared controls; deliberate Pet status inspection shares native tooltip content. Pet Target's background enable, opacity/padding and optional tint color/strength also use the shared controls. Blue Magic Learned and Phantom Roll use passive presentation and shared Extras preview/settings actions.

## Ownership and lifecycle

Action Bars uses five navigation destinations. Actions & Macros, Action Sets and Import open compact independent windows using the configuration chrome and resize geometry. Window visibility, pointer gestures, text editing and deliberate controller/keyboard navigation have separate ownership. Move/Resize/Close are stable controller controls; Confirm commits and Cancel restores a move/resize. Mouse focus alone does not capture unrelated movement or typing. Configuration keeps its own focus and gestures, and closing it preserves the workspace. The focused UI check covers window movement, resize, blur, persistence and exposed versus occluded drag/drop targets.

ABI 17 adds Action Bars crossbar settings and bank/slot/palette events to the cached host contract. Crossbar activation is independent of exclusive XIUI browsing: claimed triggers/buttons are suppressed before FFXI processing while movement and camera remain native. **Use XIUI trigger controls** enables explicit replacement. Menus, text and native targeting suspend activation; held controls drain until neutral after changes, profile loads and device replacement. Configuration → Action Bars → Crossbar → Controller supplies General, Mappings and Timing tabs. Crossbar halves remain fixed during ordered and double-tap bank changes. Action-library controller assignment uses a spatial destination picker with Confirm/Cancel, while execution stays suspended. XInput supports analog trigger hysteresis; DirectInput supports mapped digital triggers/POV. See [Action Bars](actionbars.md), P02/P03/P04 and `xiui_crossbar_input_smoke` / `xiui_actionbars_ui_smoke`. Physical devices/remappers and live actions remain unverified by these software checks.

DirectInput/XInput adapters live under `src/host/controller_input.*`; the versioned contract is `src/shared/controller_input.hpp`. ABI 16 retains the ABI 12 distinction between no capture, navigation-only capture and exclusive capture, alongside normalized events and transient status. It also carries the current target’s projected ground anchor, party world anchors and scene camera in `hud_snapshot`; the input contract is unchanged. Runtime focus routing is in `hud_runtime_controller.cpp`; configuration uses `hud_runtime_controller_config.cpp` and `input/config_controller_focus.hpp`. Module actions stay beside their modules and share operations with pointer/keyboard input.

Native input callbacks read cached ownership and append accepted actions to a bounded host mailbox without taking the runtime mutex. The render thread drains those actions and performs UI/native operations after releasing the mailbox lock. Entry capture is predicted immediately to suppress the original press/state. Live native text, action/subtarget and party-menu guards still run before suppression. Keyboard state/data callbacks read cached focus. Queued actions expire after 500 ms and are invalidated on suspension, profile changes, replacement and unload. Event callbacks and writable state/data paths share one normalizer. Observed event fields become canonical to avoid interpreting XIUI's filtered neutral state as a hardware release. State-only paths supply actions until that field has an event source. Directions repeat after 360 ms, then at 85 ms; Confirm/Cancel/Send do not repeat. Owned held fields drain until neutral after focus ends.

Disconnect/suspension, lost foreground, zoning, cutscenes, native text or action/subtarget ownership, hidden modules/HUD, profile changes, replacement and unload release XIUI focus. Native Party subtarget highlighting already follows the native cursor; XIUI does not run a second cast-confirm path.

Foreground loss preserves the expanded chat history presentation, selected tab and scroll position while releasing keyboard composition, mouse capture and controller ownership. Alt+Tab yields to Windows without closing the log, so the snipping overlay can capture it. Explicit close, native ownership changes and other lifecycle cleanup retain their normal behavior.

General → Visibility applies shared and per-module event/menu rules to HUD rendering, controller entry and focus, pointer targets, tooltips and chat text ownership. Native macro-palette exceptions affect presentation while the game retains its own input ownership. Map/interface hiding also uses native state. Hidden surfaces leave controller navigation; owned controller fields drain until neutral and canceled pointer gestures retain their release. Hidden chat keeps its draft and continues receiving history. Edit mode suspends contextual hiding for movement previews. Existing Party/alliance event and Inventory/Gil menu preferences migrate into the common policy; see [P21](implementation/21-shared-visibility-rules.md) for settings and availability fallbacks. Live context transitions and controller hardware behavior remain for Cody to check.

The ABI change requires a coordinated development host/runtime update after saving and draining settings. It cannot be installed through a runtime-only reload into the older host. Public releases still use one DLL through `scripts/package.ps1`.

## Evidence and remaining work

The host and runtime build as x86. `xiui_controller_input_smoke` checks mapping namespaces, extended mappings, state/event deduplication, ownership, directional repeat and held-state draining. `xiui_controller_smoke` checks module navigation, stable member identity, draft/send behavior, config controls and lifecycle release. These are deterministic software checks, not evidence of a connected controller.

The inspected live session has Ashita controller enumeration disabled and no confirmed controller input. Its in-process registry queries also report the controller values unavailable, so the diagnostic correctly shows unresolved bindings; the separate Windows registry observation does not prove the effective in-process map. Those settings are preserved. Cody will restart with gamepad input enabled before hardware testing. A state callback does not carry a connection-result parameter; absent callbacks become unknown/suspended after a timeout, rather than claiming a proven unplug. Hardware checks remain for XInput, DirectInput, remappers, state-copy ordering, hotplug, native gameplay and multi-member/alliance behavior.
